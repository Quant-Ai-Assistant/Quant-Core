# Обновления

[English version](../en/updates.md)

Каждый пуш в `main` этого репозитория создаёт релиз `v0.1.<сборка>`: образы сервера, Android-APK и десктопные приложения с одной и той же версией. Каждая часть обновляется сама из последнего релиза.

## Сервер

Под аккаунтом владельца сервера откройте **Settings → Updates** и нажмите кнопку обновления.

Сервис `updater` после этого:

1. читает самый новый тег релиза этого репозитория;
2. записывает в `.env` соответствующий тег образа (`sha-<коммит>`), сохраняя предыдущий;
3. скачивает новые образы и пересоздаёт `api`, `worker`, `web` и `supervisor`.

Миграции базы выполняются при старте нового `api`. Если новые контейнеры не запустились, сервис возвращает предыдущий тег образа.

То же самое можно сделать из оболочки в папке установки:

```sh
docker compose --env-file .env -f docker-compose.images.yml pull
docker compose --env-file .env -f docker-compose.images.yml up -d
```

## Android

Откройте **Account** и нажмите **Check for updates**. Если в последнем релизе сборка новее, кнопка превращается в **Install update v0.1.N**: приложение скачивает `quant.apk` и открывает системный установщик Android. В первый раз Android попросит разрешить установку из Quant.

Номер сборки в теге (`N` в `v0.1.N`) — это код версии приложения. Каждый релиз подписан одним и тем же ключом, поэтому он ставится поверх текущего приложения и сохраняет ваши данные.

## Десктоп

Десктопное приложение проверяет последний релиз при запуске и каждый час и показывает состояние в разделе обновлений приложения.

- **Windows и Linux:** обновление скачивается в фоне и ставится при перезапуске.
- **macOS:** приложение не подписано Apple Developer ID, поэтому macOS не даёт заменить его на месте. Раздел обновлений предлагает **Download 0.1.N**, и кнопка открывает последний релиз в браузере: скачайте новый `.dmg` и снова перетащите Quant в Applications.

## Быстрые обновления из main

Полный релиз собирается около 25 минут, в основном из-за сборки Android. Каждый пуш в `main` также запускает workflow `edge`, который через несколько минут после пуша публикует быстрое обновление в pre-release `edge`. Быстрое обновление содержит только JavaScript, поэтому ничего нативного не заменяет.

- **Десктоп:** проверка — в **Settings → Updates → Latest from main**. Обновление содержит веб-приложение и JavaScript сервера, около 13 МБ. Приложение проверяет его SHA-256, распаковывает рядом со своими данными и перезапускается на нём. Данные сервера, вход и настройки остаются на месте. Обновление применяется, только если у установленного приложения те же нативные части (Electron, Postgres, нативные модули). Иначе приложение сообщает, что для последних изменений нужен следующий полный релиз. Более новый полный релиз всегда заменяет более старое быстрое обновление.
- **Android:** **Account → Check for updates** сначала проверяет полный релиз, затем быстрое обновление. Когда оно готово, кнопка превращается в **Install the latest fixes**. Приложение скачивает новый JavaScript через свой сервер Quant и перезапускается на нём, без переустановки и без потери настроек. Обновление применяется, только если у установленного APK тот же нативный отпечаток (`runtimeVersion`). После нативных изменений установите полный релиз.

Первую сборку с этими возможностями всё равно нужно один раз установить из полного релиза.

## Версии

| Часть | Откуда берётся версия |
| --- | --- |
| Релиз | `v0.1.<номер запуска>` workflow `release` |
| Образы сервера | Теги `v0.1.N`, `sha-<коммит>`, `edge` и `latest` |
| Android | `versionName` `0.1.N`, `versionCode` `N` |
| Десктоп | Версия приложения `0.1.N` |
